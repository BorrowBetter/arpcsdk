Regenerate against FDR's ARPC spec 2026.22.0

- **Breaking:** `resendAgreement()` is now `resendAgreementV2()`, FDR's own operation. It's the same endpoint and body. The request type is `ResendAgreementV2Request` and the response type is `ResendAgreementV2Response` instead of `DraResponse`; `applicant` and `applicant.url` are nullable and `xCorrelationId` is added. A paused CA envelope now returns `ER40501`, and `ER40504` means the applicant or envelope is unknown.
- **Breaking (types):** `AgreementResendRequest`, `AgreementResendApplicant`, `AgreementVoidRequest`, `AgreementVoidResponse` and `AgreementErrorResponse` are gone. Use FDR's `ResendAgreementV2*`, `VoidAgreementRequest`/`VoidAgreementResponse` and `ARPCErrorResponse`. `ARPCErrorResponse.error_details` is now `ARPCErrorDetails`, which covers readiness checks and `envelope_id`. `ARPCErrorResponse.status` is `number | string`, because gateway auth errors send `"401"`.
- **Breaking (types):** `generateProgramV1()` types its 202 body as `ProgramPendingResponse`, so `data` is `LeadResponse | ProgramPendingResponse`. Check `status` before reading `application`.
- `checkEligibility()` debt accounts accept `last_payment_date`, `balance_date` and `responsibility`.
- `getApplicationStatus()` returns a typed `ApplicationStatusResponse` instead of `GetApplicationStatus200`.
- All four spec repairs are retired, because FDR fixed each one upstream.
